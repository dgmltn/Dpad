# Dpad Plan 3 of 3: UI + App Targets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Compose Multiplatform UI (`:design` system + a collapsed `:ui` feature module) and the `app-android` / `app-ios` entry points with a Koin composition root, wired to the merged `:domain`/`:data` backend, so Dpad runs as a real remote-control app pending on-device verification against Doug's hardware.

**Architecture:** `:design` holds the theme and the reusable remote-control primitives (the circular d-pad, pill buttons). `:ui` (tiny-app exception — see Global Constraints) holds all three screen families (remote, devices/pairing, shortcuts) as ViewModel-per-screen UDF composables with `@Preview`s. The app modules own the Koin composition root: they provide the three platform singletons `dataModule` requires (`DataStore` path, `Context`-bearing `MdnsBrowser`, the `named("session")` scope) and host the Navigation-3 back stack. One deferred Plan-2 item is completed here: `RemoteController.sendText` becomes a real char→keycode mapping in `:data`.

**Tech Stack:** Compose Multiplatform, Navigation 3 (multiplatform), Koin (koin-compose + koin-compose-viewmodel), androidx lifecycle ViewModel (KMP), kotlinx-collections-immutable, Kermit. Android app + iOS app (XcodeGen).

**Spec:** `docs/superpowers/specs/2026-08-11-android-tv-remote-design.md`. **Builds on:** merged `:protocol` (Plan 1) + `:domain`/`:data` (Plan 2). This is the final plan.

## Global Constraints

- Branch: `feat/ui-apps` off `main`. WIP commits per task, subject format `[design]` / `[ui]` / `[data]` / `[iOS]` / `[android]` / `[deps]` (bracketed module/topic tag first). **No `Co-Authored-By` trailer, no "Generated with Claude Code" footer, ever.** Squash-merge to `main` only at plan completion; never push.
- New dependency versions pinned to **latest stable** in `gradle/libs.versions.toml` via a live-metadata run (extend `scripts/latest-versions.sh`) — never from memory, no alpha/beta/rc.
- Project config (JDK 21, minSdk 26, compileSdk 36) lives in `gradle.properties`; read via `providers.gradleProperty(...)`.
- Android/KMP modules use the **`com.android.kotlin.multiplatform.library`** plugin (`android { }` DSL) for library modules — mirror `:protocol`/`:domain`/`:data`, whose blocks already compile under AGP 9.3.1. `app-android` is a real Android **application** (`com.android.application`). The library Android compile task is `compileAndroidMain`.
- **Tiny-app exception (explicitly taken):** the spec's Architecture lists `:remote`/`:devices`/`:shortcuts` as separate feature modules. This app is three screen-families; per Doug's KMP preferences a 2–3 screen app may collapse screens into a single UI module. Plan 3 uses ONE `:ui` module holding all three screens + their ViewModels, keeping the `:domain`/`:data`/`:design` names and the `app-*` entry shape. This is the sanctioned collapse.
- **Compose conventions (Doug's):** every Compose file has a stateful/stateless split (stateful collects the ViewModel; stateless takes plain inputs and is what previews render); `@Preview` functions for every public stateless composable, named `Preview_*`, covering meaningful states (empty/populated/disconnected/etc.); lean widget params (primitives, not whole models, when a widget uses only a few fields); icons `24.dp` (or `16.dp` when deliberately small). `@Preview` FQN: `org.jetbrains.compose.ui.tooling.preview.Preview` from `org.jetbrains.compose.ui:ui-tooling-preview` — declare the coordinate in the catalog (the `compose.*` Gradle accessors are deprecated; do not use them). Wrap preview content in the `DpadTheme`.
- **UI state:** ViewModel-per-screen, single immutable `UiState` data class exposed as `StateFlow`, UDF (events are `vm::method` callbacks). Collection-valued UiState fields use `kotlinx.collections.immutable.ImmutableList` / `persistentListOf`, never raw `List`, in composable signatures.
- **Session scope (Plan-2 carried-forward, load-bearing):** the `named("session")` `CoroutineScope` the app provides MUST be `CoroutineScope(SupervisorJob() + <main-confined dispatcher>)` — single-threaded-confined (`Dispatchers.Main.immediate` on Android; the main queue on iOS) so `RemoteSession`'s generation guard stays atomic, AND a `SupervisorJob` so a rare `DataStore`/identity failure in one child (`DevicePairer`/`RemoteController`) can't cancel the whole shared scope.
- **Full-screen remote (spec):** the remote screen is edge-to-edge with no app bar; a transparent overlay row at the top holds the device name + connection dot, keyboard icon, and power. `app-android` enables edge-to-edge.
- **iOS is compile-verified here; on-device protocol behavior (pairing/keys/discovery/TLS-1.2) is verified manually by Doug** on his Google TV set + streamer box (Task 13's checklist). Plan 3's automated gate is: ViewModels host-tested, all modules + both app targets compile, previews present.
- `:ui` and `:design` depend on `:domain` (and `:design`); they must NOT depend on `:data` or `:protocol` (the app module is the only place that sees `:data`). ViewModels consume `:domain` contracts via Koin.

### `:domain` contracts the UI consumes (exact — do not guess)

```kotlin
interface RemoteController { val connection: StateFlow<ConnectionState>; val volume: StateFlow<Volume?>
    fun connect(device: PairedDevice); fun disconnect(); fun press(key: RemoteKey)
    fun launchApp(appLinkUrl: String); fun sendText(text: String) }
interface DeviceRepository { val devices: Flow<List<PairedDevice>>; val lastUsedDeviceId: Flow<String?>
    suspend fun upsert(device: PairedDevice); suspend fun remove(id: String); suspend fun setLastUsed(id: String); suspend fun get(id: String): PairedDevice? }
interface DeviceDiscovery { fun discovered(): Flow<List<DiscoveredDevice>> }
interface DevicePairer { val progress: Flow<PairingProgress>; suspend fun start(device: DiscoveredDevice); suspend fun submitCode(code: String); fun cancel() }
interface ShortcutRepository { val shortcuts: Flow<List<Shortcut>>; suspend fun add(shortcut: Shortcut); suspend fun remove(id: String); suspend fun reorder(orderedIds: List<String>) }
interface ClientIdentityStore { suspend fun getOrCreate(): ClientIdentityHandle }
enum class RemoteKey { DPAD_UP,DPAD_DOWN,DPAD_LEFT,DPAD_RIGHT,DPAD_CENTER,BACK,HOME,VOLUME_UP,VOLUME_DOWN,MUTE,MEDIA_PLAY_PAUSE,MEDIA_REWIND,MEDIA_FAST_FORWARD,POWER }
sealed interface ConnectionState { Disconnected; Connecting; Connected; PairingRequired }   // data objects
data class Volume(val level: Int, val max: Int, val muted: Boolean)
sealed interface PairingProgress { Connecting; AwaitingCode; Paired; data class Failed(val reason: PairingFailureReason) }  // Connecting/AwaitingCode/Paired are data objects
enum class PairingFailureReason { WRONG_CODE, REJECTED, CONNECTION_LOST, TIMEOUT }
data class PairedDevice(val id:String,val name:String,val host:String,val port:Int=6466,val serviceName:String)
data class DiscoveredDevice(val name:String,val host:String,val port:Int)
data class Shortcut(val id:String,val label:String,val appLinkUrl:String)
data class CatalogApp(val key:String,val label:String,val appLinkUrl:String)
object ShortcutCatalog { val apps: List<CatalogApp>; fun toShortcut(app: CatalogApp, id: String): Shortcut }
// Koin: `dataModule` (com.dgmltn.dpad.data.di) binds all six contracts; needs the 3 platform singletons above.
```

```kotlin
package com.dgmltn.dpad.data.mapping

import remote.RemoteKeyCode

fun charToKeyCodes(c: Char): List<RemoteKeyCode> = when (c.lowercaseChar()) {
    in 'a'..'z' -> listOf(RemoteKeyCode.valueOf("KEYCODE_${c.uppercaseChar()}"))
    in '0'..'9' -> listOf(RemoteKeyCode.valueOf("KEYCODE_$c"))
    ' ' -> listOf(RemoteKeyCode.KEYCODE_SPACE)
    else -> emptyList()
}
```

```kotlin
override fun sendText(text: String) {
    text.forEach { ch -> charToKeyCodes(ch).forEach { session?.sendKey(it) } }
}
```
